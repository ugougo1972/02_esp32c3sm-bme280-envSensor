# ドキュメント責務分離ルール

## 決定

各Markdownファイルの責務を固定し、最新仕様・履歴・判断理由・進捗・試験ログを混在させない。

---

## 背景

既存文書では、以下の混在が発生していた。

- READMEに詳細仕様が集中
- 部品表に採用理由、進捗、試験結果が混在
- 電源設計文書に試験ログ、実装状況、履歴が混在
- BME280とBME680の現行状態が不一致
- AI解析時に旧仕様を現行仕様として誤認するリスクがある

---

## 採用する責務分離

| 文書・ディレクトリ | 責務 |
|---|---|
| README.md | 入口・概要 |
| CURRENT_STATUS.md | 最新状態の唯一の集約点 |
| CHANGELOG.md | 時系列変更履歴 |
| TREE.md | 構成と配置方針 |
| 10_HARDWARE/02_PARTS_LIST.md | 現行部品表 |
| 10_HARDWARE/03_POWER_DESIGN.md | 現行電源仕様 |
| 10_HARDWARE/07_HARDWARE_STATUS.md | ハードウェア実装状況 |
| 30_LOG/01_TEST_LOG.md | 試験結果 |
| 50_DECISIONS/ | 判断理由 |
| 90_HISTORY/ | 廃止仕様・旧履歴 |

---

## 禁止事項

- READMEを仕様書化しない。
- 部品表に採用理由を書かない。
- 電源仕様文書に試験ログを混在させない。
- `90_HISTORY/` の内容を現行仕様として参照しない。
- `CURRENT_STATUS.md` と矛盾する現行記述を残さない。

---

## 期待効果

- AI解析時の誤認識低減
- 長期保守性の向上
- 変更理由の追跡性向上
- GitHub運用時のレビュー容易化
- 将来のMCP / Agent連携時の参照精度向上
