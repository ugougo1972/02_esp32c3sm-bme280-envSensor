# 03_LOG_FORMAT

## 目的

本ファイルは、携帯型環境センサーロガーで記録するログデータの形式（CSVフォーマット）を定義するものである。  
ログ形式は、後から Excel、Python、R 等で解析することを前提として設計する。

## 基本方針

- ログは **CSV形式** とする
- 保存先は **microSD** とする
- 保存方式は **追記保存（append）** とする
- 文字列状態は直接保存せず、**数値コード** で保存する
- `context_code` は `04_ctx.md` の定義に従う
- `head_code` は `05_head.md` の定義に従う
- 未入力と「症状なし」「屋内」などを混同しないため、既定値を明確にする
- 初号機では、まず **安定して追記できること** を優先する
- `vbat` は **TP4056 OUT+ / OUT- を対象にした分圧回路** の実装後に追加する

## CSV項目定義（推奨最新版）

### 推奨列構成

| 列番号 | 項目名 | 内容 | 単位 / 型 | 備考 |
|--------|--------|------|-----------|------|
| 1 | date | 日付 | YYYY-MM-DD | RTC |
| 2 | time | 時刻 | HH:MM:SS | RTC |
| 3 | temp_c | 温度 | ℃ | BME280 |
| 4 | hum_pct | 湿度 | % | BME280 |
| 5 | press_hpa | 気圧 | hPa | BME280 |
| 6 | als | 照度センサ値 | count | LTR390 |
| 7 | uvs | UVセンサ値 | count | LTR390 |
| 8 | context_code | 行動状態 | code | `04_ctx.md` 準拠 |
| 9 | head_code | 頭痛状態 | code | `05_head.md` 準拠 |
| 10 | vbat | 電池電圧 | V | 分圧回路で後段実装 |

### 採用理由

- `als` / `uvs` は、現時点の実測ログと整合しやすい
- `context_code` は `04_ctx.md` の列名と意味に合わせる
- `head_code` は `05_head.md` の定義を反映する
- `vbat` は将来拡張列として末尾に置く

## CSVヘッダ

### 推奨最新版ヘッダ

```text
date,time,temp_c,hum_pct,press_hpa,als,uvs,context_code,head_code,vbat
```

### 初期段階の簡略ヘッダ例

実装段階に応じて、以下の簡略版を使ってよい。

#### RTC + BME280 + microSD

```text
date,time,temp_c,hum_pct,press_hpa
```

#### RTC + BME280 + LTR390 + microSD

```text
date,time,temp_c,hum_pct,press_hpa,als,uvs
```

#### context_code 追加版

```text
date,time,temp_c,hum_pct,press_hpa,als,uvs,context_code
```

#### head_code まで含む推奨版

```text
date,time,temp_c,hum_pct,press_hpa,als,uvs,context_code,head_code,vbat
```

## CSV記録例

### 推奨最新版の記録例

```text
2026-04-05,15:11:11,22.52,62.38,1006.26,565,0,1,1,0
2026-04-05,15:12:11,22.54,62.28,1006.23,564,0,3,2,0
2026-04-05,15:13:11,22.55,62.17,1006.26,563,0,0,0,0
```

### `vbat` 実装後の想定例

```text
2026-04-20,07:00:00,22.10,61.20,1008.01,420,0,5,1,4.102
```

### 旧段階ログとの関係

以下のような簡略ログも、開発途中の段階ログとして有効とする。

```text
2026-04-05,15:11:11,22.52,62.38,1006.26
2026-04-05,15:11:11,22.52,62.38,1006.26,565,0
```

ただし、**初号機の運用版では列順を固定する**。

## `context_code` 定義

`context_code` は `04_ctx.md` を正とする。

| code | 状態名 | 意味 |
|------|--------|------|
| 0 | unknown | 不明 / 未入力 / 未設定 |
| 1 | indoor | 屋内 |
| 2 | outdoor | 屋外 |
| 3 | moving | 移動 |
| 4 | office | 職場 |
| 5 | home | 自宅 |

### `context_code` の既定値

- 既定値は **0**
- 未入力時は **0**
- 推測で自動設定しない

## `head_code` 定義

`head_code` は `05_head.md` を正とする。

| code | 状態名 | 意味 |
|------|--------|------|
| 0 | unknown | 不明 / 未入力 / 記録なし |
| 1 | none | 頭痛なし |
| 2 | mild | 軽い頭痛 |
| 3 | moderate | 中程度の頭痛 |
| 4 | severe | 強い頭痛 |
| 5 | recovered | 軽快 |

### `head_code` の既定値

- 既定値は **0**
- 未入力時は **0**
- 推測で `1` を自動設定しない

## `vbat` 定義

### 基本方針

- `vbat` は **システム側で実際に見ている電池系電圧** とする
- 測定対象は **TP4056 `OUT+ / OUT-`**
- XIAO ADC には **分圧後の電圧** を入力し、ソフト側で元電圧へ換算する

### 既定値

- 未実装時は **0**
- 読取失敗時は **0** または異常値扱いを実装側で統一する
- 推測値を入れない

## 欠損データ・異常値の扱い

| 状態 | 記録方法 | 備考 |
|------|----------|------|
| センサ未接続 | 0 または列未採用 | 開発段階では簡略列も許容 |
| 測定失敗 | -1 または再試行失敗値 | 実装側で統一要 |
| 未入力項目 | 0 | `context_code` / `head_code` / `vbat` 等 |
| 未実装項目 | 0 または列未採用 | 段階的実装を許容 |
| RTC異常 | `2000-01-01,00:00:00` 等 | 無効データとして扱う |
| lostPower直後 | 自動再設定前の無効時刻 | 解析時除外候補 |

### 運用上の考え方

- `0` は「有効な既定値 / 未入力」の意味を持つ項目があるため、解析時に列ごとの意味を区別する
- `context_code = 0` は「unknown」
- `head_code = 0` は「unknown」
- `vbat = 0` は未実装または未取得として扱う

## ログ周期

| 項目 | 値 | 備考 |
|------|----|------|
| 基本測定周期 | 60秒 | Deep Sleep logger 基準版 |
| 試験周期 | 5秒 / 30秒 / 60秒 | periodic logger / sleep logger で使用実績あり |
| OLED表示時間 | 約5秒 | 必要時のみ |
| 残り時間 | Deep Sleep | 運用版想定 |

## 保存処理ルール

| 項目 | 内容 |
|------|------|
| 電源ON時 | ファイル存在確認 |
| ファイルなし | 新規作成 + ヘッダ書込み |
| ファイルあり | 追記 |
| SDエラー | 再試行または異常表示 |
| RTCエラー | 無効時刻扱いまたは復旧後記録 |
| Deep Sleep復帰後 | 再初期化後に追記継続 |

## microSD運用上の注意

- `SD.begin()` 失敗時は配線、CS、SPI初期化順を再確認する
- 必要に応じて以下を用いる  
  - CS High  
  - `SPI.begin(...)`  
  - `SD.begin(CS, SPI, 1000000)`
- Deep Sleep中の COM 切断は異常扱いしない
- 成立判定は Serial より **CSV追記結果を優先** する

## ファイルサイズの目安

1行あたり約 50〜80 文字程度を目安とする。

| 期間 | 行数 | サイズ目安 |
|------|------|------------|
| 1日 | 1440行 | 約100KB 前後 |
| 1週間 | 10080行 | 約700KB 前後 |
| 1ヶ月 | 43200行 | 約3MB 前後 |
| 1年 | 約52万行 | 約35MB 前後 |

**microSD 8GB 以上で十分運用可能** と見込む。  
ただし、これは概算であり、最終的な列数・文字数で増減する。

## 実装上の注意

### 1. 列名を固定する

- `context` ではなく **`context_code`**
- `head` ではなく **`head_code`**
- `lux` / `uv` ではなく、現時点の実装実績に合わせて **`als` / `uvs`** を優先する

### 2. 段階ログと運用ログを混同しない

- 単体試験や統合途中では列数が少ないログを許容する
- 運用版に入る段階でヘッダと列順を固定する

### 3. 推測値を入れない

- `context_code` をセンサ値から推定しない
- `head_code` を環境値から推定しない
- `vbat` 未実装時に仮の推定値を入れない
