# 06_POWER_CONTROL

## 目的

本ファイルは、携帯型環境センサーロガー初号機における電源制御および低消費電力動作の方針を整理するためのものである。  
初号機では、**まず Deep Sleep を用いた周期記録が成立すること** を最優先とし、厳密な消費電流最適化は完成後評価とする。

## 基本方針

- 動作モードは **USB給電試験モード** と **電池駆動想定モード** を分けて考える
- 現時点の基準点は **Deep Sleep logger 基準版**
- Deep Sleep logger は **setup() 完結型** を前提とする
- 起床ごとに RTC / BME280 / LTR390 / microSD を再初期化する
- Wi-Fi は通常運用で使用しない
- Bluetooth は通常運用で使用しない
- OLED は常時点灯せず、必要時のみ表示する
- 電流測定は完成まで実施しない
- 電池寿命の厳密見積りも後段で行う
- 電源経路は **LiPo → TP4056 → XC9306 → XIAO** を採用基準とする
- 初号機では **電源基板** と **メイン基板** を分けて考える
- Battery voltage monitor は **分圧回路追加後に有効化** する

## 電源制御の対象

本ファイルで扱う電源制御対象は以下とする。

| 項番 | 対象 | 内容 |
|------|------|------|
| P-01 | MCU動作モード | Active / Deep Sleep |
| P-02 | OLED表示制御 | 点灯 / 消灯 |
| P-03 | センサ動作制御 | 読出し時のみ使用を基本 |
| P-04 | ログ保存制御 | 必要時のみ microSD 初期化・保存 |
| P-05 | 起床周期制御 | Timer Wakeup |
| P-06 | Battery voltage monitor | 分圧回路 + ADC |
| P-07 | Encoder RGB LED | UI状態表示候補 |

## 動作モード定義

### 1. USB給電試験モード

開発・切り分け・シリアル確認を優先するモード。

| 項目 | 方針 |
|------|------|
| 給電 | USB |
| Serial Monitor | 常用 |
| logger | periodic logger / UI試験版 |
| Deep Sleep | 必要時のみ使用 |
| OLED | 確認用に表示可 |
| 優先事項 | 動作可視化・切り分け |

### 2. 電池駆動想定モード

低消費電力運用を想定したモード。

| 項目 | 方針 |
|------|------|
| 給電 | LiPo + TP4056 + XC9306 |
| Serial Monitor | 常用しない |
| logger | Deep Sleep logger |
| Deep Sleep | 基本動作 |
| OLED | 必要時のみ短時間点灯 |
| 優先事項 | 周期記録成立 |

- LiPo 外観異常なし
- LiPo 単体電圧確認済み

## Deep Sleep 方針

### 基本方針

- 1回の起床ごとに必要な処理だけ実行する
- 処理完了後は速やかに Deep Sleep に入る
- Deep Sleep 中の USB CDC 切断は異常扱いしない
- 成立判定は **Serial 出力より CSV追記結果を優先** する

### Deep Sleep 1サイクル

| 順序 | 処理 | 内容 |
|------|------|------|
| D-01 | Wakeup | Timer で起床 |
| D-02 | 初期化 | RTC / BME280 / LTR390 / microSD 初期化 |
| D-03 | RTC確認 | 現在時刻取得、lostPower / 妥当性確認 |
| D-04 | 測定 | BME280 / LTR390 読出し |
| D-05 | 保存 | CSV生成、microSD追記 |
| D-06 | 表示 | 必要なら短時間表示 |
| D-07 | Sleep設定 | 次回起床時間設定 |
| D-08 | Deep Sleep | `esp_deep_sleep_start()` |

### Deep Sleep 基準実績

| 項目 | 状況 |
|------|------|
| 30秒周期 | PASS |
| 60秒周期 | PASS |
| wakeupCause 初回 | OTHER |
| wakeupCause 以後 | TIMER |
| bootCount | 連続増加確認済み |
| CSV追記 | 継続確認済み |

### 電池駆動での扱い

- LiPo駆動で **Blink** は成立済み
- ただし、Deep Sleep logger をそのまま **電池駆動で成立したとはまだ扱わない**
- 次工程で **LiPo電源のまま Deep Sleep logger を再確認** する

## 起床後再初期化方針

Deep Sleep 復帰後は、前回動作状態を保持前提にせず、毎回再初期化する。

### 再初期化対象

| 項番 | 対象 | 理由 |
|------|------|------|
| I-01 | Wire / I2C | 通信再開のため |
| I-02 | RTC (DS3231) | 時刻取得のため |
| I-03 | BME280 | 測定再開のため |
| I-04 | LTR390 | ALS / UVS 読出しのため |
| I-05 | SPI | microSD使用前に再設定 |
| I-06 | microSD | 保存処理のため |
| I-07 | OLED | 必要時のみ再初期化 |
| I-08 | Battery ADC | `vbat` 実装後に追加 |

### 再初期化順序（推奨）

1. 起床要因取得
2. I2C初期化
3. RTC初期化
4. RTC時刻妥当性確認
5. BME280初期化
6. LTR390初期化
7. SPI初期化
8. microSD初期化
9. 必要時のみ OLED初期化
10. 必要時のみ Battery ADC準備
11. 測定・保存
12. Deep Sleep 再移行

## RTC と時刻復旧方針

### 基本方針

- RTC は DS3231 を基準時刻源とする
- Wi-Fi による常時計時同期は行わない
- RTC調整は **PC → USBシリアル → MCU → DS3231** で行う

### 異常時処理

| 状態 | 処理 |
|------|------|
| `lostPower()` 検出 | 自動再設定対象 |
| 不正時刻検出 | 自動再設定対象 |
| `2000-01-01` 系時刻 | 無効扱い |
| 復旧不可 | 無効データ扱いで記録または停止を検討 |

## OLED 制御方針

### 基本方針

- OLED は **常時点灯しない**
- 通常運用では、表示は短時間確認用とする
- Deep Sleep logger 基準版では、表示なし運用も許容する

### OLED表示ルール

| 状態 | OLED動作 |
|------|----------|
| USB給電試験中 | 表示あり可 |
| UI試験中 | 表示あり |
| periodic logger | 必要に応じ表示 |
| Deep Sleep logger | 原則短時間のみ |
| Deep Sleep 直前 | 消灯 |
| Deep Sleep 中 | 消灯 |

## センサ制御方針

### BME280

- 起床後に初期化
- 測定時に読出し
- 読出し後は保持不要

### LTR390

- 起床後に初期化
- ALS / UVS 切替時は待ち時間を入れる
- 読出し後は保持不要

### DS3231

- 起床後に読出し
- 必要時のみ書込み
- 通常は時刻取得専用

### microSD

- 保存前に初期化確認
- 保存後は次周期まで未使用
- 電池駆動時の安定性は今後確認

## microSD 初期化方針

### 基本方針

- Deep Sleep 復帰後は毎回初期化する
- `SD.begin()` の安定性を優先する
- 必要時は低速初期化を使用する

### 安定化手順候補

1. CS を High にする
2. `SPI.begin(...)`
3. `SD.begin(CS, SPI, 1000000)` を試す

## Battery voltage monitor 方針

### 回路前提

- 測定対象: **TP4056 `OUT+ / OUT-`**
- 分圧回路: **100kΩ + 100kΩ**
- ADC中点-GND 間コンデンサー: **必要時のみ 0.1µF**
- 初期はコンデンサーなしでも可

### ソフト方針

- `vbat` 未実装時は `0`
- 実装後はテスター値と比較して補正を確認する
- 低電圧警告や残量換算は後段

## Sleep移行条件

### Deep Sleep logger 基準版

以下を満たしたら Sleep へ移行する。

1. RTC読出し完了
2. センサ読出し完了
3. CSV生成完了
4. microSD保存完了
5. 必要な表示完了
6. 次回起床条件設定完了

## 起床条件

### 現時点の採用条件

| 項目 | 内容 |
|------|------|
| 主条件 | Timer Wakeup |
| 実績 | 30秒 / 60秒 |
| 判定 | 初回 OTHER、以後 TIMER を許容 |

## 低消費電力化の考え方

### 現時点で採る方針

- Wi-Fi OFF
- Bluetooth OFF
- OLED常時消灯
- 測定後すぐ Sleep
- USB給電試験と低消費電力運用を分けて考える
- RGB LED は常時点灯前提にしない

### 後段で評価する項目

- CPUクロック最適化
- 未使用GPIO処理
- 電池電圧監視の追加負荷
- OLED更新頻度最適化
- microSD初期化回数の見直し
- 実消費電流測定
- RGB LED の点灯ルール

## 電池運用に関する方針

- LiPo 1000mAh は **初期評価用の暫定容量**
- 電池容量は最終固定しない
- 容量変更可能な実装を優先する
- まずは機能成立を優先し、寿命の厳密評価は後回しとする
