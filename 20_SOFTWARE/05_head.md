# 05_head

## 目的

本ファイルは、携帯型環境センサーロガー初号機における頭痛状態入力の定義と運用ルールを整理するためのものである。  
頭痛状態は、環境ログと対応づけるための補助情報として扱い、初号機では **少数の固定コードで安定して記録できること** を優先する。

## 基本方針

- 頭痛状態は **数値コード** で扱う
- CSV本体には日本語文字列ではなく **code** を保存する
- 初号機では **手動入力** を前提とする
- センサ値から頭痛状態を自動推定しない
- 未入力時の既定値を明確にする
- 入力項目は必要最小限にとどめる
- 医療診断用途ではなく、**自己観察ログ用途** として扱う

## head_code の役割

`head_code` は、同じ環境条件でも利用者の体調状態が異なる可能性を区別するために用いる。  
主な目的は以下の通り。

- 頭痛の有無を記録する
- 軽度 / 中等度 / 強い状態を分ける
- 解析時に環境データと体調状態を対応づける
- 後から CSV を集計しやすくする

## 初号機のコード定義

| code | 状態名 | 意味 | 使用方針 |
|------|--------|------|----------|
| 0 | unknown | 不明 / 未入力 / 記録なし | 既定値 |
| 1 | none | 頭痛なし | 明確に症状なし |
| 2 | mild | 軽い頭痛 | 軽度の違和感、軽い痛み |
| 3 | moderate | 中程度の頭痛 | 日常動作に影響するが継続可能 |
| 4 | severe | 強い頭痛 | 明確に強い症状 |
| 5 | recovered | 直前まで症状があったが現在は軽快 | 状態変化の記録用 |

## 既定値

### 基本ルール

- `head_code` の既定値は **0（unknown）**
- 起動直後に入力していなければ `0` を使用する
- UI未実装段階では `0` 固定運用を許容する
- 推測で `none` を自動設定しない

### 理由

- 「入力していない」と「頭痛なし」を区別するため
- ログ解析時に未入力データを分離しやすくするため
- ソフト側が勝手に体調を決めないため

## CSV上の扱い

### 保存方針

- `head_code` は数値コードで保存する
- 日本語文字列は保存しない
- 解析時に別表で意味へ変換する

### 保存例

```text
timestamp,temp_c,hum_pct,press_hpa,als,uvs,context_code,head_code
2026-04-05 15:11:11,22.52,62.38,1006.26,565,0,1,1
2026-04-05 15:12:11,22.54,62.28,1006.23,564,0,3,2
2026-04-05 15:13:11,22.55,62.17,1006.26,563,0,0,0
```

### 03_LOG_FORMAT.md との関係

- `03_LOG_FORMAT.md` に頭痛列を追加する場合は、本ファイルの定義を正とする
- 初号機で未実装の期間は、CSV列未追加でもよい
- 将来追加時は `head_code` という列名を推奨する

## UI入力方針

### 初号機の前提

- 入力UIは **Rotary Encoder** を前提とする
- 初号機では複雑な入力画面を作り込まなくてよい
- 少なくとも以下のいずれかで運用可能とする  
  - 常に `0` 固定  
  - MENU配下で変更  
  - LOG前後に簡易選択  
  - 状態変更時のみ入力

### 想定方式候補

| 方式 | 内容 | 状況 |
|------|------|------|
| A | MENUから選択変更 | 候補 |
| B | LOG画面で状態変更 | 候補 |
| C | ボタン操作で簡易切替 | 候補 |
| D | 未実装期間は `0` 固定 | 暫定運用可 |

## 入力タイミング方針

### 推奨タイミング

| タイミング | 内容 |
|-----------|------|
| 起床後 | その時点の状態を入力 |
| 症状変化時 | 状態が変わったら更新 |
| ログ確認時 | まとめて更新 |
| UI試験段階 | 未入力なら `0` のままでもよい |

### 運用ルール

- 状態が変わったときだけ更新してもよい
- 毎回入力必須にはしない
- 入力漏れは `0` として残してよい

## 状態定義の運用ルール

### 1. unknown（0）

以下の場合に使用する。

- 入力していない
- 状態が判断しづらい
- UI未実装段階
- 記録忘れ

### 2. none（1）

以下を目安に使用する。

- 頭痛症状がない
- 明確な違和感がない
- 通常状態として扱いたい

### 3. mild（2）

以下を目安に使用する。

- 少し痛い
- 軽い圧迫感がある
- 気になるが日常動作には大きな支障がない

### 4. moderate（3）

以下を目安に使用する。

- はっきり頭痛がある
- 集中しづらい
- 日常動作には影響があるが継続可能

### 5. severe（4）

以下を目安に使用する。

- 強い頭痛
- 明確に活動しづらい
- 横になりたい、休みたいレベル

### 6. recovered（5）

以下を目安に使用する。

- 直前まで症状があったが軽快した
- 改善局面を記録したい
- 痛み残りがあっても「悪化側」ではなく「回復側」として見たい

## 選択優先ルール

状態が迷う場合は、以下のルールを用いる。

| 条件 | 推奨 |
|------|------|
| 入力していない | 0 |
| 症状なしが明確 | 1 |
| 少し違和感がある | 2 |
| はっきり痛い | 3 |
| 強くつらい | 4 |
| 改善中を記録したい | 5 |

### 境界で迷う場合

- 迷ったら重く見積もらず、**保守的に低い側でもよい**
- ただし毎回基準が変わりすぎないよう、自分なりの基準を固定する
- 初号機では厳密性より継続記録を優先する

## context_code との関係

`head_code` は `context_code` と併用できる。

### 例

| context_code | head_code | 解釈例 |
|--------------|-----------|--------|
| 5 (home) | 1 (none) | 自宅で頭痛なし |
| 4 (office) | 2 (mild) | 職場で軽い頭痛 |
| 3 (moving) | 3 (moderate) | 移動中に中程度の頭痛 |
| 2 (outdoor) | 4 (severe) | 屋外で強い頭痛 |
| 0 (unknown) | 0 (unknown) | 未入力 |

## 解析時の扱い

### 基本方針

- `head_code` は補助情報として使う
- `0` を含むデータもログ自体は有効とする
- 集計時に `0` を除外して比較できるようにする

### 解析例

- `head_code = 1` と `head_code >= 2` で環境差を比較する
- `moderate` / `severe` 発生時の気圧や温湿度を見る
- `moving` と `moderate` が同時に多いかを見る
- `recovered` 前後の環境変化を見る

## 実装上の注意

### 1. 自動推定しない

- センサ値から頭痛状態を自動決定しない
- 気圧低下や温湿度差だけで `head_code` を決めない

### 2. コード追加を急がない

- 初号機では 0〜5 の範囲で固定する
- `nausea`, `aura`, `medicated` などの細分化は後段で検討する

### 3. ログとの整合を保つ

- `03_LOG_FORMAT.md` に列追加する場合は列名・意味を一致させる
- 実装コード側の定数名も本ファイルと一致させる
