# 03_トラブルシューティング(03_TROUBLESHOOTING)

## 基本方針

- 不具合発生時は最小構成へ戻す
- 電源、配線、通信、ソフトの順で切り分ける
- 未確認事項を推測で確定しない
- 直前に変えた要素を優先確認する
- 合格済み構成を基準点として残す

---

## 最小構成の定義

### MCU単体最小構成

- XIAO ESP32S3 Plus
- USB給電のみ

### I2C最小構成

- MCU
- 対象I2Cデバイス1個
- 3.3V
- GND
- SDA
- SCL

### 電源確認最小構成

- LiPo
- TP4056
- XC9306
- テスター
- MCU未接続

※ 完成まで電流測定は実施しないため、ここでのテスターは主に電圧確認用として扱う。

### 記録系最小構成

- MCU
- microSDモジュール
- 3.3V
- GND
- SPI配線のみ

---

## 事前確認チェックリスト

### 共通

- 半田ブリッジはないか
- ピンが傾いていないか
- 部品の向きは正しいか
- GNDが共通になっているか
- 配線の差し間違いはないか
- 使用しているGPIO定義は実配線と一致しているか

### 電源

- 供給電圧は適正か
- 極性は正しいか
- 3.3V系へ5Vを誤印加していないか
- 電源投入時に過熱部品はないか

### I2C

- SDA / SCL が逆でないか
- 対象デバイスのアドレスは認識できているか
- 対象が本当にI2Cモードになっているか

---

## 1. 書込みできない / ボードが認識されない

### 症状

- Arduino IDE で書込みに失敗する
- ポートが表示されない
- 書込み途中で止まる
- シリアルモニタが開けない

### 対処の基準点

- XIAO単体へ戻す
- `USB CDC On Boot = Enabled` を確認する
- Blink または最小 heartbeat スケッチへ戻す

### 判定

- 単体で書込みできるなら、外部配線起因の可能性が高い
- 単体でも失敗するなら、USB・設定・基板不良を疑う

---

## 2. 起動しない / リセットを繰り返す

### 症状

- 電源投入後に何も起きない
- シリアル出力が出ない
- 繰り返し再起動する
- 一瞬起動して落ちる

### 対処

1. XIAO単体へ戻す
2. USB給電で確認する
3. LiPo系では `3V3-GND` を測る
4. 3.3VとGNDの短絡を確認する
5. 部品を1個ずつ戻す

### 判定

- 単体起動OKで追加時に不安定なら、配線または電源容量の問題
- 単体でも不安定なら、基板・書込み・給電の問題

---

## 3. I2Cデバイスが見えない

### 症状

- I2Cスキャンでアドレスが出ない
- 一部デバイスだけ認識されない
- 複数接続で不安定になる

### XIAO ESP32S3 Plus での I2C基準点

- D4(GPIO5) = SDA
- D5(GPIO6) = SCL

### 判定

- 個別で見えて統合で見えないなら配線共有部を疑う
- 個別でも見えないなら対象デバイス側を疑う

---

## 4. BME280が読めない / 値がおかしい

### 症状

- begin() に失敗する
- Chip ID が合わない
- 温度が極端に高い / 低い
- 値が固定のまま変化しない

### 既知の基準点

- I2Cアドレス 0x76
- Chip ID 0x60
- 補正係数読出し済み
- 手計算確認済み

### 判定

- 0x60 が読めればBME280本体は概ね正常
- 単体で正常なら統合時の配線または競合を疑う

---

## 5. LTR390のALSまたはUVが不安定

### 症状

- ALSが0のまま
- UVSが0のまま
- ALS/UVS切替後に値が安定しない
- periodic logger で ALS が一定値のまま変化しない

### 対処

1. まず ALS固定で確認する
2. 明暗変化を与えて ALS の追従を見る
3. UVSは室内で0付近を許容する
4. ALS/UVS切替時は待ち時間を入れる
5. LTR390単体へ戻す

### 判定

- ALS固定で変化するなら基本動作は正常
- UVSが室内で0中心でも即異常とはしない
- 修正版 periodic logger で ALS が数百〜1万台まで変化するなら、固定問題は解消したと判断する

---

## 6. OLEDに文字が出ない / 一部しか出ない

### 症状

- 初期化は通るが表示が出ない
- 真っ暗
- 一部だけ点灯
- 表示が詰まって読みにくい

### 対処

1. 単独文字表示へ戻す
2. ヘッダのみ、本文のみ、フッタのみで切り分ける
3. 固定文字列のみ表示する最小スケッチへ戻す
4. 画面クリアと更新タイミングを見直す

### 判定

- 単独文字表示ができればOLED基本動作は正常
- センサ値のみ崩れるならレイアウトまたは描画処理を疑う

---

## 7. DS3231 が認識しない / 時刻が保持されない

### 症状

- I2Cで見えない
- 時刻読出しが失敗する
- 再起動ごとに時刻が戻る
- `lostPower()` が出る

### 対処

1. DS3231単体でI2C認識確認する
2. 固定時刻書込みスケッチを実行する
3. PCシリアル経由設定を確認する
4. 再起動後の読出しを比較する
5. `lostPower()` と `rtc.now()` を確認する

### 判定

- 設定直後のみ正しいなら保持系を疑う
- 主電源断後に再発する場合はバックアップ保持の最終判定を保留とする

---

## 8. microSD が初期化できない / 書けない

### 症状

- カード初期化失敗
- ファイルを作れない
- 書込み途中で失敗する
- Deep Sleep統合時だけ `SD.begin` に失敗する

### 対処

1. SD初期化だけの最小スケッチで試す
2. 単純な1行テキスト書込みへ落とす
3. `pinMode(CS, OUTPUT)` → `digitalWrite(CS, HIGH)` → `SPI.begin(...)` → `SD.begin(CS, SPI, 1000000)` を試す
4. RTC 側で先に停止していないか確認する

### 判定

- 初期化成功でCSVだけ失敗ならソフトウェア処理の問題
- 初期化自体失敗なら配線またはカード・電源の問題

---

## 9. RGB LED付きロータリーエンコーダが誤動作する

### 症状

- 回した方向と逆になる
- 1クリックで複数回反応する
- 押し込みが不安定
- RGB LED が点灯しない
- メニューカーソルが飛ぶ

### 既知の基準点

- D0(GPIO1) → A
- D1(GPIO2) → B
- D3(GPIO4) → SW
- D11(GPIO38) → LED R
- D12(GPIO39) → LED G
- D13(GPIO40) → LED B
- ESP32Encoder + PCNT 方式
- 右回転 = CW
- 左回転 = CCW
- 5ノッチ = 5イベント
- PUSH / RELEASE 正常

### 対処

1. 回転方向だけ確認する最小スケッチへ戻す
2. A / Bを入れ替えて挙動比較する
3. 押し込みは別スケッチで単独確認する
4. RGB LED は各色単独点灯スケッチで確認する
5. `encAccum` または PCNT 設定を確認する

### 判定

- CW/CCW が 5ノッチ = 5イベントで取れるなら回転系は正常
- RGB LED だけ不良なら LED配線と抵抗値を疑う
- 回転は正常で UIだけ不安定なら状態遷移側を疑う

---

## 10. Deep Sleep から正しく復帰しない

### 症状

- 起床しない
- 起床しても処理が進まない
- COMポートが消えて不安定に見える

### 既知の基準点

- XIAO ESP32S3 Plus + DS3231 + BME280 + LTR390 + microSD 構成で 30秒 / 60秒周期は USB給電で成立済み
- `setup()` 完結型
- `bootCount` 連続増加確認済み

### 対処

1. Deep Sleep前後にシリアルログを入れる
2. 起床後は毎回初期化する
3. 試験成否は Serial Monitor ではなく CSV を優先して判定する
4. MCU単体へ戻して起床だけ確認する

### 判定

- 最小構成で起床できるなら、追加部品初期化の問題
- COM切断のみで CSV が連続追記されているなら、即異常とはしない

---

## 11. 電源系接続後に動かない

### 症状

- USBでは動くがLiPo系では動かない
- 3.3Vが出ない
- 部品が熱い
- 起動してもすぐ落ちる

### 既知の基準点

- LiPo 単体: 4.002V 安定
- TP4056 単体: PASS
- XC9306 単体: `O-G = 3.290V` 安定
- XIAO `3V3-GND = 3.288V` 安定
- LiPo駆動 Blink: PASS

### 対処

1. LiPo単体電圧を測る
2. TP4056 `OUT+ / OUT-` を測る
3. XC9306 `I-G` と `O-G` を測る
4. XIAO未接続で 3.3V 出力確認
5. XIAO単体だけ戻して Blink で確認する

### 判定

- 無負荷で3.3Vが出ないなら電源系単体不良を疑う
- XIAO単体は動くが追加で落ちるなら電源余裕不足または配線不良を疑う

---

## 12. XC9306 の向きが分からない / 半田付けを進められない

### 症状

- ピンヘッダ実装方向に自信がない
- 入出力を逆接続しそうで不安

### 基準点

- `I = 入力`
- `G = GND`
- `O = 出力`

### 対処

1. 端子名ベースで判断する
2. 先に無通電で接続図を書く
3. 不安なら半田付け前に再度 `I / G / O` を確認する

### 判定

- 端子名ベースで入出力が説明できるなら実装判断可能
- 説明できないなら、まだ半田付けしない方が安全

---

## 13. battery monitor の値がおかしい

### 症状

- `vbat` が高すぎる / 低すぎる
- 値が大きく揺れる
- テスター値と合わない
- ADCに 0V しか入らない

### 主な原因候補

- 分圧回路の結線違い
- R1 / R2 の値違い
- ADCピン違い
- GND共通漏れ
- 換算式ミス
- `TP4056 OUT+` を直接 ADC へ入れている
- 必要に応じたコンデンサ未追加

### 対処

1. 100kΩ + 100kΩ の 1:1 分圧か確認する
2. 中点が ADC、下側が GND になっているか確認する
3. テスターで `OUT` 電圧と中点電圧を別々に測る
4. ソフト側の換算式を確認する
5. 値の揺れが大きければ 0.1µF を ADC-GND 間へ追加検討する

### 判定

- 中点電圧が `OUT` の約半分なら分圧回路は概ね正常
- ADC値だけずれるなら、GPIO指定または換算式を疑う

---

## 14. 症状が不定で再現しない

### 症状

- たまに失敗する
- 配線を触ると変わる
- 同じスケッチでも成功したり失敗したりする

### 対処

1. 配線を短くする
2. ジャンパワイヤを交換する
3. ブレッドボード位置を変更する
4. 仮半田部分を再確認する
5. 最小構成へ戻して再現性を取る

### 判定

- 機械的に触ると変わるなら接触不良の可能性が高い
- 完全にランダムなら電源または実装品質も疑う

---

## 15. 原因が特定できない場合の戻り先

原因が分からなくなった場合は、以下の順で戻す。

1. 外付け部品を全て外す
2. XIAO単体で書込み確認する
3. XIAO単体で Blink / シリアル出力確認する
4. I2Cデバイスを1個だけ戻す
5. 表示を戻す
6. 記録系を戻す
7. 電源系を戻す
8. battery monitor は最後に戻す

---

## 判断保留とする条件

以下は即故障判定しない。

- 室内で UVS が 0 付近
- ALS / UVS切替直後の一時的な0
- Deep Sleep中の COM 切断
- RTC復旧前に保存された 2000/01/01 の試験用ログ1行
- `vbat` 未実装期間の `0`
