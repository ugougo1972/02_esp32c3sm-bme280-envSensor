# 03_要求仕様(03_REQUIREMENTS)

## 動作時間

06:00 〜 23:00（17時間）
充電なしで連続稼働

### 動作時間補足

- 電池容量は現時点で最終固定しない
- LiPo は初期評価用の暫定容量として扱う
- 運用途中で容量を増減できる実装方針を優先する
- 完成まで電流測定は実施せず、電池寿命の最終評価は完成後に行う

---

## 記録周期

1分

### 周期動作試験補足

- 試験用として 5秒周期 periodic logger を用いる
- Deep Sleep 周期起床試験では 60秒周期および30秒周期を確認済み
- Deep Sleep 周期起床時は、起床ごとに 1回測定して 1行CSV追記する構成を基準とする

---

## 記録方式

microSDへCSV保存

### 記録系補足

- 初期検証では `/log.csv`、`/log_env.csv`、`/log_env_loop.csv`、`/log_sleep_env.csv` を試験用ファイルとして扱う
- 実運用時は列順を固定し、再起動後も追記可能であること
- 旧形式の試験ファイルと実運用ファイルを混在させないこと
- Deep Sleep 周期起床試験では `timestamp,temp_c,hum_pct,press_hpa,als,uvs,boot_count,wakeup_cause` 形式を確認済み

---

## 省電力方針

- Wi-Fi OFF
- Bluetooth OFF
- Deep Sleep 使用
- OLED 常時消灯
- 測定・保存後すぐ Sleep
- Deep Sleep 時に AE-TPS63802 の EN 端子を LOW にしてセンサ電源を完全遮断する

### Deep Sleep 補足

- Deep Sleep 復帰後は毎回必要な初期化をやり直す前提とする
- USB CDC の COM ポートは Deep Sleep 中に切断され得るため、Deep Sleep 試験の合否は CSV 追記結果を優先して判定する
- Deep Sleep 実消費電流は完成まで未測定とし、別途最終評価で扱う
- TPS63802 EN 端子の GPIO 制御により、センサ類への 3.3V 供給を完全遮断できる
- GPIO43(TPS63802_EN)はRTC GPIO非対応のためDeepSleep中Hi-Z化する可能性がある→回路側100kΩプルアップで対策（R_EN）
- microSD は DeepSleep 時に地味に電流を消費するため、Sleep前に CS=HIGH固定と SPI.end() を実施すること

---

## ユーザー入力

RGB LED付きスイッチ付きロータリーエンコーダ

### 入力内容

- 移動ログ
- 頭痛ステータス
- 基本画面遷移操作

### 入力系補足

- 右回転を CW、左回転を CCW とする
- 5ノッチ = 5イベントを成立条件とする
- PUSH / RELEASE を区別して扱う
- RGB LED は MCP23017（I2C GPIO Expander）経由で制御する
- RGB LED 各色に 100Ω の電流制限抵抗を設ける
- Encoder復帰はGPIO1/2/3がRTC GPIO対応のためEXT0/EXT1で復帰可能

OLED 0.96インチ

- 操作時のみ表示
- 測定後5秒表示
- メイン画面では以下を優先表示する
  - 温度
  - 湿度
  - 気圧
  - ALS
  - UV
- 現行試作レイアウトでは以下の並びを基本とする
  - 1行目: 温度 / 湿度
  - 2行目: 気圧
  - 3行目: ALS / UV
- メニューは常時表示ではなく、押下時に別画面として表示する
- 上段には時刻欄と電池アイコンの配置余地を持たせる
- センサー測定数値の文字サイズ・フォントは統一方針とする
- 128x64 OLED のまま UI 改善を優先し、128x128化やカラー化は後段検討とする

## センサ要件

### BME280

- 温度測定が可能であること
- 湿度測定が可能であること
- 気圧測定が可能であること
- 3.3V系で動作すること
- I2C接続可能であること

### LTR390

- ALS（照度系指標）が取得可能であること
- UVS（UV系指標）が取得可能であること
- 3.3V系で動作すること
- I2C接続可能であること
- 室内低UV環境で0付近を取り得ることを許容する
- ALS / UVS 切替直後の一時的な0を異常扱いしない
- ALS / UVS 切替を含む連続ログ試験で値が固定化しないこと
- ALS / UVS 切替時は新データ待ちと安定待ち時間を考慮すること
- Deep Sleep 周期起床試験でも ALS / UVS の再取得が継続すること

### OLED

- I2C接続で文字表示が可能であること
- センサ値の複数項目同時表示が可能であること
- 操作用メニュー表示に使用可能であること
- 時刻欄および電池アイコンの表示試作が可能であること

## RTC要件

### DS3231

- I2C接続可能であること
- 現在日時を保持できること
- 主電源断後もバックアップ条件下で時刻保持できること
- 通常運用時の正時刻源として利用できること
- PCからUSBシリアル経由で時刻設定できること
- インターネット時刻同期はPC側で実施し、ESP32は受信日時をDS3231へ反映する方式とする
- `lostPower()` 検出時に時刻再設定できること
- 2000/01/01 などの不正時刻を検出できること
- 試験時は不正時刻検出後に自動再設定できること
- Deep Sleep 周期起床時の時刻源として利用できること

## 電源要件

### 最小電源経路

- LiPo → TP4056 → AE-TPS63802 → XIAO ESP32S3 Plus の給電経路が成立すること
- LiPo駆動で XIAO ESP32S3 Plus が起動し、最小スケッチを実行できること
- TP4056 充電入力時に異常発熱・異臭がないこと
- AE-TPS63802 出力で 3.3V 系が安定すること
- AE-TPS63802 の EN 端子を GPIO で制御し、Deep Sleep 時にシャットダウンできること

### 電源実装方針

- 初号機では USB通信用USB と LiPo充電用USB を分離する
- 初号機では電源回りを別基板化することを第一候補とする
- LiPo ←→ TP4056 は JST コネクタ接続を前提とする
- 電源基板 ←→ メイン基板は端子台経由ケーブル接続を前提とする
- 電源基板は LiPo / TP4056 / AE-TPS63802 を基本範囲とする
- 分圧回路はメイン基板側に実装することを第一候補とする

### 電源基板構成

| 部品 | 仕様 | 備考 |
|------|------|------|
| TP4056 | 充電・保護モジュール | USB-C入力 |
| AE-TPS63802 | 昇降圧スイッチング 3.3V出力 | EN端子付き |
| C1 | 0.1uF MLCC（極性なし） | TP4056 OUT+ ↔ OUT- 間 |
| C2 | 47uF 電解（極性あり） | TPS63802 VOUT ↔ GND 間 |
| C3 | 0.1uF MLCC（極性なし） | TPS63802 VOUT ↔ GND 間（C2と並列） |
| 端子台 | 4ライン | 3.3V / GND / VBAT_RAW / EN |

### 端子台ライン構成

| ライン | 内容 | 接続先 |
|--------|------|--------|
| 3.3V | TPS63802 VOUT出力 | メイン基板 3.3V |
| GND | GNDバス | メイン基板 GND |
| VBAT_RAW | TP4056 OUT+直接引き出し | メイン基板 ADC分圧回路 |
| EN | TPS63802 EN端子 | XIAO D6(GPIO43) |

### 線材

| 区間 | 線材 |
|------|------|
| JST ↔ TP4056 B+/B- | AWG24（直付け） |
| その他全配線 | AWG28 |
| GNDバス・3.3Vライン | スズメッキ線 |

### battery voltage monitor 要件

- `TP4056 OUT+ / OUT-` を測定対象とする
- XIAO D3(GPIO4) の ADCで読めること（ADC1_CH3）
- ADC入力には分圧回路を入れること（メイン基板側に実装）
- 初期値は `100kΩ + 100kΩ` の 1:1 分圧を第一候補とする
- 必要に応じて ADC中点-GND 間へ安定化用コンデンサーを追加できること
- `vbat` の値はテスター実測と概ね整合すること

## GPIO割り当て

### XIAO ESP32S3 Plus ピン確定

| XIAO端子 | GPIO | 用途 | 特性 |
|----------|------|------|------|
| D0 | GPIO1 | Encoder_A | RTC GPIO対応 |
| D1 | GPIO2 | Encoder_B | RTC GPIO対応 |
| D2 | GPIO3 | Encoder_SW | RTC GPIO対応 |
| D3 | GPIO4 | Battery_ADC(ADC1_CH3) | RTC GPIO対応 |
| D4 | GPIO5 | I2C_SDA | 確定 |
| D5 | GPIO6 | I2C_SCL | 確定 |
| D6 | GPIO43 | TPS63802_EN | RTC GPIO非対応→100kΩプルアップで対策 |
| D7 | GPIO44 | SPI_CS | UART RX兼用・USB CDC主体で通常GPIO利用可 |
| D8 | GPIO7 | SPI_SCK | 確定 |
| D9 | GPIO8 | SPI_MISO | 確定 |
| D10 | GPIO9 | SPI_MOSI | 確定 |
| D16 | GPIO10 | 予約 | 未使用 |

### スケッチ作成上の注意点

1. **GPIO43(TPS63802_EN)のDeepSleep対応**：RTC GPIO非対応のため、DeepSleep中にHi-Z化する可能性がある。回路側100kΩプルアップ(R_EN)で対策済み。

2. **GPIO44(SPI_CS)のUART兼用**：UARTデバッグが必要な場合は別ピンへの変更を検討すること。初号機ではUSB CDC主体のためGPIO44利用は可能。

3. **GPIO43/44の両線転用**：UART両線がセンサGPIOに転用されているため、UARTデバッグは利用不可。

4. **microSD CS処理**：DeepSleep前に以下を実施すること：
   ```cpp
   pinMode(PIN_SPI_CS, OUTPUT);
   digitalWrite(PIN_SPI_CS, HIGH);
   SPI.end();
   ```

5. **Encoder復帰**：GPIO1/2/3はRTC GPIO対応のため、EXT0/EXT1によるDeepSleep復帰が可能。Encoder_SW(GPIO3)での復帰も実装可能。

## MCU運用方針

- 最終構成の主候補MCUは XIAO ESP32S3 Plus とする
- センサ・表示の評価は ESP32-WROOM系開発ボードでも実施可能とする
- 評価用MCUと最終MCUでピン定義は分けて管理する
- XIAO ESP32S3 Plus のUSBシリアル確認では Arduino IDE の `USB CDC On Boot = Enabled` を前提条件として扱う
- XIAO ESP32S3 Plus の裏面JTAGランド（GPIO38/39/40）は使用しない
- LED R/G/B 制御は MCP23017（I2C GPIO Expander）で代替する

## MCU変更による消費電力前提の変更

MCUを ESP32-C3 系想定から ESP32-S3 系主候補へ見直したため、
DeepSleep時消費電流の前提値は再評価対象とする。

- ESP32-C3 DeepSleep: 約10〜20µA（参考値）
- ESP32-S3 DeepSleep: 約20〜50µA（参考値）

### 変更理由

- 電池寿命計算に影響するため
- 実ボード差、周辺回路差の影響が大きいため
- 評価用MCUと最終MCUを分けて確認する必要があるため

※ 実測値は基板・周辺回路・電源方式に依存するため、完成後に実測する。

## 初号機実装方針

- 初号機はユニバーサル基板ベースとする
- センサ、RTC、記録、電源は既製モジュール活用を前提とする
- 電池は交換・容量変更しやすい構成を優先する
- 専用基板化は初号機とは分離して後段で検討する
- ハンダ作業は共晶ハンダ（鉛入り）を使用し、温度は **280℃** を基準とする
- 全配線は 2.54mm ピッチで統一する
- OLED / LTR390 / Encoder はケース直付けとし、AWG28ケーブルでメイン基板と接続する
- メイン基板にはEN維持用プルアップ抵抗(R_EN 100kΩ)を配置する
